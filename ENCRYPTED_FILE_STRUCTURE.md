# Структура зашифрованных файлов

## Общая информация

Все файлы, зашифрованные с помощью Files-V, имеют единую структуру, которая обеспечивает безопасное хранение и возможность проверки целостности данных.

## Формат файла

```
+------------------------+
| Магическая подпись    | 8 байт
+------------------------+
| Хеш ключа (SHA-256)   | 32 байта
+------------------------+
| Размер данных         | 4 байта
+------------------------+
| Вектор инициализации  | 16 байт
+------------------------+
| Зашифрованные данные  | Переменная длина
+------------------------+
```

## Детальное описание полей

### 1. Магическая подпись (8 байт)
- Фиксированная последовательность: `0xFE 0xED 0xFA 0xCE 0xCA 0xFE 0xDE 0xAD`
- Используется для идентификации зашифрованных файлов
- Позволяет быстро определить, зашифрован файл или нет
- Не содержит секретной информации

### 2. Хеш ключа (32 байта)
- SHA-256 хеш от пароля шифрования
- Используется для проверки правильности пароля при расшифровке
- Не позволяет восстановить оригинальный пароль
- Обеспечивает быструю проверку пароля без расшифровки данных

### 3. Размер данных (4 байта)
- Размер оригинальных (незашифрованных) данных
- Хранится в формате little-endian (uint32)
- Используется при расшифровке для обрезки данных до правильного размера
- Позволяет корректно обрабатывать файлы любого размера

### 4. Вектор инициализации (16 байт)
- Случайно генерируемый для каждого файла
- Используется в режиме CFB алгоритма AES
- Обеспечивает уникальность шифрования даже при одинаковых данных и пароле
- Предотвращает атаки на основе одинаковых блоков

### 5. Зашифрованные данные (переменная длина)
- Данные, зашифрованные алгоритмом AES-256 в режиме CFB
- Используют вектор инициализации из предыдущего поля
- Размер может быть больше оригинальных данных из-за особенностей шифрования
- Содержит все оригинальные данные в зашифрованном виде

## Технические детали

### Алгоритм шифрования
- Используется AES-256 в режиме CFB
- Пароль дополняется нулями до 32 байт для AES-256
- Каждый файл имеет уникальный вектор инициализации
- Проверка пароля происходит до начала расшифровки данных

### Безопасность
- Магическая подпись не снижает безопасность
- Хеш пароля не позволяет восстановить пароль
- Уникальный IV для каждого файла предотвращает атаки
- Размер данных хранится в открытом виде, но это не влияет на безопасность

### Ограничения
- Минимальный размер зашифрованного файла: 60 байт
- Максимальный размер оригинальных данных: 4 ГБ (ограничение uint32)
- Размер зашифрованных данных может быть больше оригинальных

## Пример использования

Для анализа структуры зашифрованного файла можно использовать утилиту `analyze`:

```bash
go run cmd/analyze/main.go путь/к/зашифрованному/файлу
```

Утилита выведет подробную информацию о структуре файла, включая:
- Магическую подпись и её валидность
- Хеш ключа в шестнадцатеричном формате
- Размер оригинальных данных
- Вектор инициализации
- Начало зашифрованных данных

## Примечания

- Структура файла может быть изменена в будущих версиях
- При изменении структуры будет обновлена магическая подпись
- Старые версии программы могут не поддерживать новую структуру
- Рекомендуется всегда использовать последнюю версию программы
