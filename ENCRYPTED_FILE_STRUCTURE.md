# Структура зашифрованного файла

## Заголовок файла (64 байта)

1. Магическая подпись (8 байт)
   - Фиксированное значение: `0xFE 0xED 0xFA 0xCE 0xCA 0xFE 0xDE 0xAD`
   - Используется для идентификации зашифрованных файлов

2. Принцип шифрования (4 байта)
   - Версия принципа (1 байт)
   - Количество алгоритмов (1 байт)
   - Для каждого алгоритма:
     - Тип алгоритма (1 байт)
     - Режим работы (1 байт)
   - Количество проходов (1 байт)

3. Хеш ключа (32 байта)
   - SHA-256 хеш ключа шифрования
   - Используется для проверки правильности ключа при расшифровке

4. Размер данных (4 байта)
   - Размер оригинальных данных в байтах (uint32, little-endian)

5. Вектор инициализации (16 байт)
   - Случайно сгенерированный IV для каждого файла

## Поддерживаемые алгоритмы шифрования

### Типы алгоритмов
- AES-128 (0)
- AES-192 (1)
- AES-256 (2)
- ChaCha20 (3)

### Режимы работы
- ECB (Electronic Codebook)
- CBC (Cipher Block Chaining)
- CFB (Cipher Feedback)
- OFB (Output Feedback)
- CTR (Counter)
- GCM (Galois/Counter Mode)
- CCM (Counter with CBC-MAC)

## Формат принципа шифрования

Принцип шифрования может быть задан в виде строки:
```
<алгоритм1>-<режим1>+<алгоритм2>-<режим2>+...+x<количество_проходов>
```

Примеры:
- `AES256-CFB` - один проход AES-256 в режиме CFB
- `AES256-CFB+ChaCha20+x2` - два прохода: AES-256 в режиме CFB, затем ChaCha20
- `AES128-CBC+AES256-GCM` - один проход AES-128 в режиме CBC, затем AES-256 в режиме GCM

## Зашифрованные данные

После заголовка следуют зашифрованные данные. Размер зашифрованных данных может отличаться от размера оригинальных данных в зависимости от используемых алгоритмов и режимов шифрования.

## Версионирование

Текущая версия формата файла: 1.0.0

Структура версии:
- Major (1 байт) - основная версия, несовместимые изменения
- Minor (1 байт) - обратно совместимые изменения
- Patch (1 байт) - исправления ошибок

## Безопасность

- Каждый файл использует уникальный вектор инициализации
- Поддерживается множественное шифрование с разными алгоритмами
- Хеш ключа используется для предотвращения попыток расшифровки с неверным ключом
- Размер оригинальных данных сохраняется для корректного восстановления файла

## Технические детали

### Алгоритм шифрования
- Используется AES-256 в режиме CFB
- Пароль дополняется нулями до 32 байт для AES-256
- Каждый файл имеет уникальный вектор инициализации
- Проверка пароля происходит до начала расшифровки данных

### Ограничения
- Минимальный размер зашифрованного файла: 60 байт
- Максимальный размер оригинальных данных: 4 ГБ (ограничение uint32)
- Размер зашифрованных данных может быть больше оригинальных

## Пример использования

Для анализа структуры зашифрованного файла можно использовать утилиту `analyze`:

```bash
go run cmd/analyze/main.go путь/к/зашифрованному/файлу
```

Утилита выведет подробную информацию о структуре файла, включая:
- Магическую подпись и её валидность
- Хеш ключа в шестнадцатеричном формате
- Размер оригинальных данных
- Вектор инициализации
- Начало зашифрованных данных

## Примечания

- Структура файла может быть изменена в будущих версиях
- При изменении структуры будет обновлена магическая подпись
- Старые версии программы могут не поддерживать новую структуру
- Рекомендуется всегда использовать последнюю версию программы
